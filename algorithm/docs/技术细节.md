# 算法部分：8 通道 sEMG → CNN-Transformer 手势识别

用公开数据集 **NinaPro DB2** 训练了一个 CNN-Transformer，把 8 通道表面肌电映射成
手势类别（可以只映射成上位机自带的 6 种手势，也可以做 NinaPro 的 17 种动作）。
训练好的模型通过一个纯 NumPy 插件(`plugins/*.py`)直接挂到上位机「手势交互」页，
**上位机不需要装 PyTorch**。

同一个主干也支持**连续输出**：不加分类头、改成回归头，就能每 25 ms 输出一组
连续关节角（Cyberglove 21 路，排除第 20 路），对应"连续测试 / 连续控制"的方案——
见第八节。离散和连续两种模型都可以用同一套代码训练，只差一个 `--task` 参数。

## 零、大白话版：这套东西到底是怎么做出来的

把这个算法想成**教一个小孩认手部动作**：

```
① 找教材        公开数据集 NinaPro（别人早就录好的 40 个人做手势的肌电）
      ↓
② 挑内容        只留 8 条通道（跟你们手环的 8 个电极对得上），不要第 20 号那个人
      ↓
③ 洗干净        滤掉工频嗡嗡声和高频杂音（20-450 Hz 带通 + 50 Hz 陷波）
      ↓
④ 剪成小片      把长长的录音剪成一段段 100 毫秒的小片子（滑窗）
      ↓
⑤ 分三堆        第 1/3/4 次做的当练习册，第 6 次当模拟考，第 2/5 次留作期末考
      ↓
⑥ 教小孩        让 CNN-Transformer 反复看"小片子 + 当时在做哪个动作"，学着认
      ↓
⑦ 考试          用期末考那堆（小孩从没见过的第 2/5 次）打分，画成绩单和错题本
      ↓
⑧ 抄成小册子    把学到的"经验"从 PyTorch 抄成普通 NumPy 格式（几百 KB）
      ↓
⑨ 装进软件      上位机导入一个 .py 插件，就能实时认出动作（不用装 PyTorch）
```

两句话概括：

* **模型** = 一个"看肌电认动作"的小孩：先看局部波形（卷积），再联系前后文（注意力），
  最后给出判断。
* **成绩可信** = 期末考试用的是小孩没见过的动作片段，练习册、模拟考、期末考互不重叠；
  我们还专门写了两个小程序（`audit_split.py`、`recheck_clean.py`）复查有没有"偷看"。

## 一、数据：为什么是 NinaPro DB2、为什么取 1–8 通道

**数据集**：`算法/公开数据集/Ninapro/DB2`，NinaPro DB2 —— 40 位健全受试者、每人 6 次重复、
每次重复做 17 个手部动作（练习 B）+ 休息，采样率 2 kHz。
每个 `.mat` 里的变量：

| 变量 | 含义 |
| --- | --- |
| `emg` (T×12) | 12 路 sEMG。**第 1–8 路**是沿前臂一圈均匀分布的 8 个电极（腕肘之间），第 9–10 路在指浅屈肌/指总伸肌，第 11–12 路在肱二/三头肌 |
| `glove` (T×22) | Cyberglove 22 路关节角（未标定原始值） |
| `stimulus` / `restimulus` | 动作标签（`restimulus` 是官方事后重标注，时间对齐更好，默认用它） |
| `repetition` / `rerepetition` | 第几次重复（用来划分训练/测试） |

**为什么只取 1–8 通道**：本项目手环就是 8 通道（ADS1298 八路），
而 DB2 的第 1–8 路正好是“前臂一圈 8 电极”的布置，跟手环的佩戴方式最接近，
所以只取这 8 路，训练出来的模型和你们的硬件通道数、电极思路是对得上的。

**排除 20 号**：配置里 `exclude_subjects=(20,)`（受试者 20 号不参与训练），
角度分支同理排除第 20 路（`angle_exclude_channels=(20,)`）。这两个开关都在
`src/config.py` 里，改一行就能换。

> 附：我们顺手做过一次全 40 位受试者的信号体检（见下），20 号受试者的第 1 路
> 幅度是别人的 7 倍、第 6 路几乎为 0（电极脱落/接触不良的典型表现），排除它是合理的。

| 受试者 | 8 通道 RMS（µV，第1路 … 第8路） |
| --- | --- |
| S19（正常） | 34.9 26.2 16.8 20.4 38.8 7.1 14.6 50.7 |
| **S20（异常）** | **285.7** 27.6 24.9 69.2 8.0 **0.2** 347.9 34.7 |
| S21（正常） | 34.9 20.6 16.2 13.1 7.8 3.6 9.4 51.9 |

（40 位受试者的中位数：39.2 24.3 22.7 19.8 8.1 7.7 26.3 42.6 µV）

## 二、数据怎么切、怎么划分（这一步最影响“成绩真不真实”）

1. **滑窗**：窗口 `W = 200` 点 = **100 ms**（2 kHz），窗口标签取窗口**末端时刻**的类别
   （和项目书 2.3.4 节一致）。训练步长 200（窗口不重叠，省算力且信息冗余不大），
   测试步长 50（25 ms，滑窗更密，评估更平滑）。
2. **划分按“第几次重复”，不随机切窗口**：

| 用途 | 重复次数 |
| --- | --- |
| 训练 | 第 1、3、4 次 |
| 验证（早停用） | 第 6 次 |
| 测试 | 第 2、5 次 |

   重叠窗口如果随机划分，同一段动作会同时出现在训练集和测试集里，
   准确率会被明显高估——这是肌电论文里最常见的坑，我们用整段重复来切，杜绝信息泄漏。
3. **丢掉过渡段**：`rerepetition = 0` 的是记录开始/结束的过渡段，没有有效标签，窗口直接丢掉。
   同理丢掉映射不到上位机 6 种手势的动作（`--label-mode app6` 时）。

## 三、预处理：和上位机**逐点一致**（这是能不能落到实机上的关键）

上位机 `core/signal_processor.py` 的链路是：
`20–450 Hz 带通 → 50 Hz 陷波 → 一阶直流阻断 → 每 50 ms 输出一个特征块(含滤波后波形)`。

**训练时的预处理必须和它完全一致**，包括两点：

1. **因果滤波**：用 `scipy.signal.sosfilt` 逐点推进（`StreamingFilter`，
   连初始状态 `sosfilt_zi` 的用法都和上位机一模一样），而不是离线论文常用的零相位 `filtfilt`。
2. **因果滚动标准化**：每个时刻只用“当前及之前 30 s”的统计量做逐通道 z-score
   （`rolling_zscore`），和插件运行时用最近 30 s 滑窗估计均值方差的做法一致。

> 为什么非要这样？我们实测过：拿**离线流程(零相位滤波 + 整段标准化)**训练出来的模型，
> 如果直接接到上位机的在线链路上，测试集准确率会从 0.78 掉到 0.59，
> **“仅动作样本”准确率从 0.51 掉到 0.17**（见下表）。原因是相位/幅频响应和标准化基准都变了，
> 网络看到的输入分布跟训练时不一样。把训练管线改成和上位机一致后，实机才复现得出实验室指标。

| 训练时用的预处理 | 离线测试准确率 | 仅动作样本 |
| --- | --- | --- |
| 零相位滤波 + 整段标准化（论文常规做法） | 0.777 | 0.511 |
| 零相位滤波 + 滚动标准化 | 0.591 | 0.173 |
| **上位机因果滤波 + 整段标准化** | 0.585 | 0.000 |
| **上位机因果滤波 + 滚动标准化（本项目采用）** | 见第五节 | 见第五节 |

（上表在同一模型、同一测试集上只改预处理，S1 受试者）

## 四、CNN-Transformer 模型

输入 `(8, 200)`（8 通道 × 100 ms），张量流动如下：

```
(8,200)
 ├─ Conv1d(8→32, k=5, padding=2) → BN → ReLU → MaxPool(2)      # 局部时域波形/爆发特征
 ├─ Conv1d(32→64, k=5, padding=2) → BN → ReLU → MaxPool(2)     # (64,50)
 ├─ + 正弦位置编码                                              # 让注意力知道先后顺序
 ├─ Transformer 编码器 × 2 层
 │     每层 = 多头自注意力(8 头) + 残差 + LayerNorm
 │            + 深度可分离卷积前馈(depthwise k=3 → pointwise 128 → 64) + 残差 + LayerNorm
 ├─ 时间维全局平均池化 (GAP) → Dropout(0.2)
 └─ 全连接 → Softmax：18 类（0=休息 + 17 个动作）   [或 7 类：0=休息 + 6 种上位机手势]
```

参数量约 **8 万**，一次前向（单帧 100 ms）在普通 CPU 上是毫秒级，完全可以实时。

**为什么 CNN + Transformer 这么搭**：

* 1D-CNN 的卷积核只覆盖局部几十毫秒，擅长抓“肌电爆发点、波形局部形状”，参数少、好训练，
  但它感受野有限，很难直接看到“屈肌发力时伸肌在干什么”这种跨通道、跨时刻的关系；
* 自注意力让每个时间片都能直接和任意其它时间片、其它通道做加权比较，
  正好补上“跨肌肉协同、动作过渡”的长程依赖；
* 编码器里用**深度可分离卷积**替代标准两层全连接前馈，是项目书里写的轻量化措施，
  参数量和乘加次数都明显下降，为以后往 ESP32-S3 上搬留了余量。

## 五、训练与结果

**统一设置**：DB2 练习 B、只取 sEMG 1–8 通道、窗口 100 ms（200 点 @2 kHz）、
逐受试者各训一个模型、S1–S8 共 8 人（20 号受试者排除）、
训练/验证/测试 = 重复 1/3/4 : 6 : 2/5，模型参数约 **8 万**。

## 六、怎么跑到上位机里

1. 打开上位机 → 左侧「手势交互」页 → 「导入算法 .py」；
2. 选 `算法/plugins/手势识别_CNNTransformer.py`（离散手势）
   或 `算法/plugins/连续关节角_CNNTransformer.py`（**连续输出关节角，连续方案用这个**）；
3. 插件和权重放在同一目录（`模型权重_手势.npz` / `模型权重_连续关节角.npz`
   + `推理引擎_纯NumPy.py`），
   拷贝的时候整个 `plugins/` 一起拷；
4. 连上手环、开始采集，前 1.7 s 插件在攒数据（输出“无”），之后每 50 ms 给一次结果。

插件内部做的事情：

* 把上位机每 50 ms 给的一块数据攒起来，凑够 **100 ms（200 点）**再送模型；
  如果采样率是 1 kHz（每块 50 点），会先线性重采样到 200 点，**两种采样率都能用**；
* 用最近 30 s 的滑窗统计量做逐通道 z-score（和训练时一致）；
* 18 类模型会把概率按语义映射到上位机的 6 种手势（映射表见 `src/config.py` 的
  `APP_GESTURE_MAP`），7 类模型直接输出；
* 对后验概率做指数平滑，减少跳变；置信度不够或落在“其它动作”上时输出“无”。

## 七、复现步骤

```bash
# 0) 依赖（训练用，上位机跑插件只需要 numpy）
pip install -r 算法/requirements.txt

# 1) 训练（逐受试者，每人一个模型；S1–S8）
cd 算法/src
python train.py --mode per-subject --subjects 1-8 --epochs 30 --norm-window 30

# 2) 画图 + 打印指标
python evaluate.py --run ../outputs/ex1_persubject_gesture --per-class-table

# 3) 导出纯 NumPy 权重（会顺带做 torch/numpy 数值一致性校验）
python export_numpy.py --ckpt ../outputs/ex1_persubject_gesture/best.pt --copy-to-plugin gesture

# 4) 端到端回放验证（用上位机自带的解释器跑，环境里没有 torch）
```

## 八、连续模式：每 25 ms 输出一组关节角（改成"连续测试"用这一节）

项目书里写的是**离散**的手势分类（6 个类别 + 置信度），而连续控制要的是
"每时每刻输出当前的手部姿态"——也就是把 8 通道 sEMG 回归成**连续关节角**。
上位机的算法接口本来就支持这一类（`TYPE="angles"`，界面会逐拍显示各关节角度），
所以从离散切到连续不需要改上位机，只要换训练目标 + 换插件。

### 8.1 怎么从分类改成回归

同一个 CNN-Transformer 主干（卷积 + 注意力 + 全局池化），只换输出头：

| | 离散模式（项目书原方案） | 连续模式（本次新增） |
| --- | --- | --- |
| 输出 | 7 / 18 类 Softmax 概率 | **21 路关节角**（连续值） |
| 损失 | 交叉熵 | **均方误差 MSE**（标准化目标） |
| 训练命令 | `--task gesture`（默认） | `--task angles`（纯回归）/ `--task both`（多任务） |
| 上位机插件 | `手势识别_CNNTransformer.py` | `连续关节角_CNNTransformer.py` |

回归目标就是同一批 `.mat` 里的 Cyberglove 22 路**排除第 20 路**后的 21 路
（对应你说的"角度取除了 20 号的"）。

### 8.2 连续回归的三个关键处理

1. **关节角目标低通 5 Hz**（`--angle-smooth 5`）。真实手部姿态的变化基本在 5 Hz 以内，
   手套原始信号里的高频抖动是传感器噪声，肌电本来也预测不出来，不滤掉就是让网络去学噪声。
2. **回归目标取窗口末尾 25 ms**（`--angle-target tail`），而不是整窗平均——
   整窗平均会把目标"往回拖"半个窗口，输出会滞后，连续控制里这个滞后是要命的。
3. **验证集逐通道仿射校准**（默认开，`--no-calibrate` 可关）。
   回归网络常犯两个毛病：预测幅度偏小（向均值收缩）、不同通道有不同偏置。
   在**验证集**上拟合 `y ≈ a·ŷ + b`（逐通道最小二乘），只用一个乘法加一个加法就能修掉，
   参数存在权重文件里，插件自动应用。**注意只用验证集拟合，不碰测试集**。

### 8.3 连续模式结果（测试集 = 第 2/5 次重复）

4 位受试者、每人一个模型、各训练 40 轮，窗口 100 ms，测试步长 25 ms，
结果按"逐通道算完再平均"：

| 指标 | 数值 |
| --- | --- |
| 关节角 **R²** | **0.471** |
| 逐通道平均**皮尔逊 r** | **0.680** |
| MAE（按 0~90° 显示口径） | **7.6°** |

每位受试者（同一套配置、各自一个模型）：

| 受试者 | S1 | S2 | S3 | S4 |
| --- | --- | --- | --- | --- |
| R² | 0.502 | 0.431 | **0.552** | 0.398 |
| 平均 r | 0.698 | 0.653 | **0.743** | 0.625 |
| MAE | 7.09° | 8.36° | 7.24° | 7.89° |

逐通道（4 人平均，通道号是 Cyberglove 原始编号，已排除第 20 路）：

| 通道 | #5 | #8 | #13 | #17 | #9 | #6 | … | #7 | #19 | #3 | #2 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| r | 0.80 | 0.80 | 0.80 | 0.80 | 0.79 | 0.78 | … | 0.49 | 0.51 | 0.52 | 0.55 |

即：**手指屈伸相关的通道预测得最好（r≈0.8，也就是说预测曲线跟真实曲线的形状基本吻合）**，
前臂旋前/旋后那几路最差（r≈0.5）——因为 8 个"围一圈"的电极对旋前/旋后肌不敏感。

### 8.4 对照：连续 vs 离散、窗口长度

| 配置（同一受试者 S1） | R² | 平均 r | MAE |
| --- | --- | --- | --- |
| 多任务（分类 + 回归一起训，22 轮） | 0.332 | 0.587 | ≈9.0° |
| **纯回归 + 目标低通 + 末尾目标 + 仿射校准（本方案，40 轮）** | **0.502** | **0.698** | **7.09°** |
| 纯回归但窗口改成 200 ms（窗口加长） | 0.476 | 0.674 | 7.31° |

结论：① 把分类损失去掉、专心做回归，精度明显提升；② 100 ms 的窗口已经够用，
再拉长到 200 ms 反而略差（参数一样多、时间分辨率变粗）。

### 8.5 连续模式的局限（很重要）

* Cyberglove 是**未标定**的原始值，跟真实角度只成正比，没有单位。所以现在
  "MAE 7°"是按"±3σ 映射到 0~90°"的口径折算的，**绝对值不要当真，看趋势和相关性**。
  要拿真实角度，得用自己的手套/角度传感器采一批数据，按你们的量纲重新训（管线已经写好了，改配置就行）。
* 逐通道看，手指屈伸类通道最好（r 0.82~0.85），前臂旋前/旋后的通道最差（r 0.33~0.45）——
  因为这些动作主要靠旋前圆肌/旋后肌，而 8 个"围一圈"的电极对它们不敏感。
* 目前是**逐人模型**。跨人用时建议先做 30 s 校准，或者用本人几分钟的数据微调。

## 十、上位机采数据 → 用户迁移（个人化微调）

跨度用场景要解决的是"**同一个模型换到别人身上就不准了**"。做法分两层：

| 层次 | 在哪做 | 需要什么 | 效果 |
| --- | --- | --- | --- |
| **① 免训练自适应** | **上位机内部**（插件里已经实现） | 什么都不用 | 每路电极的滚动标准化会自动跟着佩戴者调整，解决"幅度量纲不同" |
| **② 监督微调（推荐）** | 上位机外面的 PC（要 PyTorch） | 该用户自己做的 3~5 分钟动作 + 参考角度 | 把通用模型调成"他自己的模型" |

### 10.1 完整流程（六步）

```
① 上位机「交互训练」页选好方案 → 采集（每个动作做 5~6 轮）
      存成 training_日期.csv（表头：timestamp,gesture_code,CH1..CH8）
      ↓
② 同步采集参考角度（数据手套/动捕/弯曲传感器），另存一份带时间戳的 CSV
      ↓
③ 按时间戳合并成自采格式：
      python merge_app_csv.py --app-csv ... --ref-csv ... --out D:/自采数据/S01_ses1.npz --subject 1
      ↓
④ 微调（冻结卷积前端 + 小学习率，20 轮以内）：
      python finetune.py --base ../plugins/模型权重_连续关节角.npz \
          --data-dir "D:/自采数据" --subjects 1 --epochs 20 --lr 2e-4 --freeze-front \
          --out "../plugins/模型权重_连续关节角.npz"
      ↓
⑤ 上位机「手势交互」→ 重新导入插件（插件会自动加载新权重）
      ↓
⑥ 之后这个人再用，就是"他自己的模型"
```

### 10.2 实测效果（用公开数据集模拟"换人"）

把在 S3 上训好的连续角度模型，直接用到 S2 身上，再用 S2 自己的数据微调：

| 阶段 | R² | 平均 r | MAE | 
| --- | --- | --- | --- |
| 直接用通用模型（换人） | **−0.206** | 0.230 | 12.19° |
| 用本人 3 次重复微调 16 轮 + 重新校准 | **+0.242** | 0.481 | 9.85° |

（同一人从零训练是 R² 0.43，说明微调还有提升空间：加数据、解冻前端、多训几轮都能继续涨）

**结论**：不微调，通用模型换到新人身上基本不可用（R² 为负 = 还不如直接猜平均值）；
本人 3~5 分钟的数据微调后就能用起来。这条正好可以写成论文里的"**个性化适配**"实验。

### 附：划分审计与泄漏检查（`audit_split.py` / `recheck_clean.py`）

1. **三份数据按整段重复划分**：训练=第 1/3/4 次、验证=第 6 次、测试=第 2/5 次，
   窗口不跨大段，杜绝"相邻重叠窗口被随机分到训练/测试两边"这种最常见的泄漏。
2. **查到一处真实的小瑕疵**：NinaPro 的标签在重复段边界处是直接切换的，
   而我们的窗口长 100 ms，所以有极少数窗口会"跨边界"——窗口末尾属于本段，
   但开头几十毫秒是上一段的动作尾巴。比例：训练 0.72%、验证 1.12%、测试 1.14%
   （每人约 33/17/135 个窗口），这些窗口的末端标签 **100% 是"休息"**。
3. **量化影响**：把跨边界窗口全部剔除（`require_same_repetition=True`），
   用已训好的模型在严格划分上重新评估（`recheck_clean.py`，**不重训**）：

| 实验 | 原指标 | 严格划分 | 变化 |
| --- | --- | --- | --- |
| 7 类上位机手势（8 人合并准确率） | 0.7166 | **0.7219** | +0.0053 |
| 7 类宏平均 F1 | 0.5541 | **0.5607** | +0.0066 |
| 18 类 NinaPro 动作（8 人合并准确率） | 0.6735 | **0.6736** | +0.0001 |
| 连续关节角 R²（4 人合并） | 0.4714 | **0.4739** | +0.0025 |
| 连续关节角平均 r | 0.6818 | **0.6837** | +0.0019 |

   剔除之后指标**全部略微上升**（因为这些窗口是"标签为休息、输入里却混着动作"的难样本），
   也就是说目前报告的数字是**偏保守**的，不是靠跨段窗口刷出来的。
   "仅动作样本准确率"更是完全不变（0.6671 -> 0.6671），因为跨段窗口的标签都是休息。
4. **验证集的每一项用途**：早停、选最优权重（离散看准确率/宏 F1，连续看 R²）、
   连续模式的逐通道仿射校准。这三件事只用第 6 次重复，测试集（第 2/5 次）全程未参与。
   类别权重只由训练段的类别分布算出；在线模式的标准化是**因果滚动**统计量，不跨集取样。
5. **关节角目标 5 Hz 低通不是泄漏**：它同时作用于训练目标和测试真值，
   而模型输入永远是"过去 100 ms"的因果信号。实测把预测直接跟**原始（未低通）手套**算相关：
   S1 0.700 / S2 0.655 / S3 0.745 / S4 0.627，比跟低通真值算的（0.698/0.653/0.743/0.625）
   **还略高一点**——说明没有靠"平滑真值"把相关性抬高。

## 附录 B：这个模型是黑箱吗？——两个"开箱"实验

**结论先说**：训练结果是**一组固定的数字**（本项目 45 个张量、83,145 个数，约 325 KB；
其中 3,200 个是不参与训练的正弦位置编码，其余约 8 万是训练出来的**参数**）。
但它不是"每个时刻的肌电值各配一个权重"这种简单形式，原因见下。

### B1 参数都花在哪了（7 类手势模型，受试者 S1）

| 模块 | 数字个数 | 是什么 |
| --- | --- | --- |
| `conv1` | 1,280 | 32 个长度为 5 的一维卷积核（8 通道 → 32 通道） |
| `bn1` / `bn2` | 386 | 批归一化的缩放/偏移（+运行统计量） |
| `conv2` | 10,240 | 64 个长度为 5 的卷积核（32 → 64 通道） |
| `encoder.0` + `encoder.1` | 67,456 | 2 层 Transformer：Q/K/V 投影、输出投影、前馈层、层归一化 |
| `norm` | 128 | 最后的层归一化 |
| `head_gesture` | 455 | 输出层（64 → 7 类） |
| `pos_enc` | 3,200 | 固定的正弦位置编码（**不训练**） |

### B2 实验一：遮挡某一路电极（`channel_importance.py`）

把某一路输入整段置零（标准化后 0 = 该通道均值，等价于"这一路没信号"），看测试指标掉多少：

| 去掉的通道 | 总体准确率 | 仅动作样本准确率 |
| --- | --- | --- |
| 不遮挡（基准） | 0.8594 | 0.6833 |
| **通道 6** | 0.8183 | **0.4798（掉 20.4 个点）** |
| **通道 5** | 0.8237 | **0.4404（掉 24.3 个点）** |
| **通道 1** | 0.8340 | 0.4551（掉 22.8 个点） |
| 通道 7 | 0.8354 | 0.5838（掉 9.9 个点） |
| 通道 2/3/4/8 | 变化很小 | 掉 0~3 个点 |

### B3 实验二：梯度归因 / 敏感度地图（`saliency.py`）

算 8896 个测试窗口的 `|∂输出/∂输入|` 再平均，得到"通道 × 时刻"的敏感度地图
（`outputs/ex1_persubject_app6/saliency.png`）：

* 最敏感的三路是 **通道 1、5、6**，和遮挡实验的结论**互相印证**；
* 敏感度是**弥散**的：最灵敏的 10% 的（通道,时刻）单元只占总敏感度的 16.4%
  （完全均匀是 10%），时间上四等分分别是 29.6% / 23.9% / 21.8% / 24.8%；
* 也就是说：**没有"某一时刻一票定音"这种事**，模型是综合整个 100 ms、多路电极投票。

### B4 为什么不能说"每个时刻的肌电值各有一个权重"

因为网络里有三类**非线性/输入相关**的运算：

1. **ReLU/GELU**：只保留正值，同一个数值在不同上下文里"通不通过"不一样；
2. **最大池化与 Softmax**：取最大、做归一化，都是输入相关的选择；
3. **自注意力**：注意力权重本身就是由输入算出来的（`softmax(QK^T/√d)`），
   所以"哪个时刻重要"是**随窗口变化**的。

只有在一个工作点附近做**一阶泰勒展开**，才会得到一张"8×200 的局部权重表"——
也就是 B3 里那种敏感度图，但它**每个样本都不一样**，不是全局固定的一张表。

### B5 训练过程本身算黑箱吗？

分两层看：

* **训练过程：不算黑箱。** 它是**梯度下降**（沿损失下降方向迭代更新参数），
  每一步都有明确定义；我们全程留了记录——每轮的训练/验证损失与指标
  （`metrics.json` 的 `history`、`train_log.txt`）、最优轮次、参数量、随机种子，
  同一条命令重跑可复现。推理阶段没有随机性，同一输入必然同一输出
  （PyTorch 与纯 NumPy 两套实现的结果误差 <1e-6）。
* **模型的决策逻辑：算是黑箱。** 我们没法用一句话说明"为什么这一次判成握拳"，
  只能靠扰动实验、归因分析去**近似**它。

| 方法 | 能看到什么 |

| 注意力可视化 | 2 层 × 8 头注意力矩阵，看模型是否关注动作起始/爆发段 |
| 逐类敏感度图 | 分别画出"握拳/张开/捏合"各自的敏感通道与时刻 |
| 最小充分输入实验 | 只保留最敏感的几十毫秒/几路电极，看指标能保住多少（指导降采样与电极裁剪） |
| 蒸馏成简单模型 | 用决策树/逻辑回归去拟合网络输出，得到"人能读懂"的近似规则 |

### A1 数据与标注

| 术语 | 解释 | 本项目 |
| --- | --- | --- |
| **sEMG**（表面肌电） | 肌肉收缩时在皮肤表面测到的微弱电位变化，幅值几十~几百 µV | 前臂 8 路 |
| **通道**（channel） | 一路独立的传感器信号；8 通道 = 8 个电极同时采集 | 取 NinaPro 第 1–8 路 |
| **采样率** f_s | 每秒采样点数；由奈奎斯特定理，能表示的最高频率是 f_s/2 | 2000 Hz（最高 1000 Hz） |
| **标签 / ground truth** | 每个时刻"正确答案"是什么（做哪个动作 / 关节角多少） | 分类用 `restimulus`，回归用 `glove` |
| **重标注**（relabeling） | 官方事后把动作起止时间重新对齐后的标签，比原始 `stimulus` 更准 | 默认用重标注 |
| **受试者**（subject）/ **试次**（trial）/ **重复**（repetition） | 第几个人 / 第几次做某个动作 / 一共做了几轮 | 40 人 × 6 次重复 |
| **关节角**（joint angle） | 手指/手腕各关节的弯曲角度，连续量 | Cyberglove 22 路，排除第 20 路 |
| **未标定**（uncalibrated） | 传感器输出与真实物理量成正比但没换算成标准单位 | Cyberglove 原始值 |

### A2 预处理

| 术语 | 解释 | 本项目 |
| --- | --- | --- |
| **带通滤波**（band-pass filter） | 只保留某个频段的成分，滤掉更低和更高的 | 20–450 Hz |
| **巴特沃斯滤波器**（Butterworth） | 通带最平坦的一类滤波器，用阶数控制下降陡峭程度 | 4 阶 |
| **工频干扰 / 陷波**（notch） | 电网 50 Hz 及其谐波串进信号；陷波 = 只在这个窄频段做抑制 | 50 Hz，Q=30 |
| **直流偏置 / 直流阻断**（DC blocker） | 电极极化造成的缓慢漂移，用一阶高通去掉 | 一阶 IIR |
| **因果滤波**（causal）vs **零相位滤波**（zero-phase, filtfilt） | 前者只用当前与过去的数据（可实时），后者正反各滤一次、无相位失真（必须拿到整段数据） | 训练与上位机统一用**因果** |
| **相位失真 / 群延迟** | 因果滤波会让不同频率成分延迟不同，波形形状轻微变形 | 通过对齐训练/部署链路消除 |
| **标准化 / z-score** | 把每路信号减均值、除标准差，让不同人的幅度量纲一致 | 逐通道 z-score |
| **滚动标准化**（rolling normalization） | 只用"当前及之前一段窗口"的统计量做标准化（因果） | 30 s 窗 |
| **训练-部署一致性 / 域偏移**（domain shift） | 训练时和上线时的数据分布不一致，会让实机精度明显掉 | 见第三节实测 |

### A3 样本构造与划分

| 术语 | 解释 | 本项目 |
| --- | --- | --- |
| **滑窗**（sliding window） | 用固定长度的窗口在连续信号上滑动，切成一条条样本 | 窗长 W=200 点 |
| **窗长 / 步长 / 重叠率** | 窗口长度 / 相邻窗口间隔 / 两者的重叠比例 | 100 ms；训练步长 200（不重叠）、测试步长 50（25 ms，75% 重叠） |
| **数据泄漏**（data leakage） | 任何"测试信息进入训练或选型"的情况，会让成绩虚高 | 按重复段整段划分来杜绝 |
| **留出法**（hold-out） | 把数据分成训练/验证/测试三份 | 1/3/4 训练、6 验证、2/5 测试 |
| **交叉验证**（cross-validation） | 轮流留一部分做测试、重复多次，结果更稳 | 未做（可扩展） |
| **类不平衡**（class imbalance） | 各类样本数差很多；本数据"休息"占一半以上 | 休息占 50–78% |
| **类别权重**（class weighting） | 给少数类更大权重，避免模型"一直猜多数类" | `--class-weight balanced` |
| **数据增强**（data augmentation） | 人为制造变化，提升泛化 | 10–30 dB 信噪比高斯白噪声、时间翻转 |
| **信噪比**（SNR, dB） | 信号功率与噪声功率之比的对数，值越小噪声越大 | 10–30 dB |
| **泛化**（generalization）/ **过拟合**（overfitting） | 对没见过的数据也有好表现 / 只在训练数据上表现好 | 用验证集早停抑制 |

### A4 模型结构

| 术语 | 解释 | 本项目 |
| --- | --- | --- |
| **张量**（tensor） | 多维数组；网络内部的输入输出都是张量 | 输入 (8, 200) = 通道×时间 |
| **一维卷积**（Conv1d） | 一个小窗口（卷积核）沿时间滑动做加权求和，提取局部波形特征 | Conv1d(8→32, k=5)、Conv1d(32→64, k=5) |
| **卷积核 / 感受野** | 卷积核长度 / 一个输出点能看到多长的输入 | k=5（2.5 ms） |
| **批归一化**（BatchNorm） | 在批内对特征做标准化，加速收敛、稳定训练 | 每层卷积后 |
| **激活函数**（ReLU / GELU） | 引入非线性，否则多层网络等价于一层 | ReLU / GELU |
| **池化**（max pooling） | 相邻若干个点取最大，降长度、增强小幅位移的不变性 | MaxPool(2)，两次 → 200→50 |
| **Transformer / 自注意力**（self-attention） | 让每个时间点与所有时间点两两比较并加权求和，建模长程依赖 | 2 层编码器 |
| **多头注意力**（multi-head）/ Q、K、V | 把特征拆成多组并行做注意力（每组关注不同的关系）；Q=查询、K=键、V=值 | 8 头 |
| **位置编码**（positional encoding） | 注意力本身不含顺序信息，用正弦函数把位置注入 | 正弦编码 |
| **前馈网络**（FFN）+ **深度可分离卷积** | 逐点非线性变换；深度可分离卷积把标准卷积拆成"深度+逐点"两步，参数更少 | d=64→128→64，k=3 |
| **残差连接**（residual）/ **层归一化**（LayerNorm） | 把输入直接加到输出上（缓解深层退化）/ 在特征维归一化（稳定训练） | Pre-LN 结构 |
| **全局平均池化**（GAP） | 在时间维取平均，得到与序列长度无关的定长向量 | 50 → 64 维 |
| **Dropout** | 训练时随机丢弃一部分神经元，防止过拟合 | 0.2 |
| **Softmax / 分类头** | 把输出变成各类概率 / 输出类别的最后一层 | 18 类或 7 类 |
| **回归头 / 多任务学习** | 输出连续值的最后一层 / 一个主干同时干多件事 | 21 路关节角；`--task both` |
| **参数量** | 网络可训练的数字个数 | 约 8.1 万 |

### A5 训练

| 术语 | 解释 | 本项目 |
| --- | --- | --- |
| **损失函数**（loss） | 衡量"预测与答案差多少"的分数，训练就是让它变小 | — |
| **交叉熵**（cross-entropy） | 分类常用损失；**标签平滑**（label smoothing）把硬标签软化，防止过度自信 | 平滑 0.02 |
| **均方误差**（MSE） | 回归常用损失：误差平方的平均 | 关节角回归 |
| **反向传播 / 梯度** | 从损失往回算每个参数的"该往哪调" | — |
| **梯度裁剪**（gradient clipping） | 限制梯度大小，防止训练爆炸 | 阈值 5 |
| **优化器 / AdamW** | 决定怎么用梯度更新参数；AdamW = 自适应学习率 + 解耦权重衰减 | lr=1e-3，wd=1e-4 |
| **学习率调度 / 余弦退火** | 学习率随训练轮次变化的策略；余弦退火按余弦曲线平滑下降 | `--cosine` 默认开 |
| **批次 / 轮次**（batch / epoch） | 一次喂多少样本 / 把训练集完整过一遍叫一轮 | 批 128，20–40 轮 |
| **早停**（early stopping） | 验证指标连续若干轮不提升就停止，防止过拟合 | 耐心 6–8 轮 |
| **模型选择 / checkpoint** | 按验证指标挑"最好那一轮"的权重并保存 | 分类看准确率/宏 F1，回归看 R² |

### A6 评估

| 术语 | 解释 | 本项目 |
| --- | --- | --- |
| **准确率**（accuracy） | 预测对的比例，简单但受类别不平衡影响 | 7 类 0.717、18 类 0.674 |
| **平衡准确率 / 宏平均 F1** | 各类指标先算再平均，不受类别多少影响 | 宏 F1 0.554 |
| **精确率 / 召回率**（precision / recall） | 报出来的里有多少是真的 / 真的里有多少被找出来 | 见各类表格 |
| **混淆矩阵**（confusion matrix） | 一张"真实类别×预测类别"的表，看谁常被认成谁 | 已出图 |
| **R²**（决定系数） | 回归指标：1 表示完美，0 表示和"只猜平均值"一样好 | 连续角度 0.471 |
| **MAE / RMSE** | 平均绝对误差 / 均方根误差 | MAE 7.6°（显示口径） |
| **皮尔逊相关系数** r | 衡量预测曲线和真实曲线的形状相似度（-1~1） | 平均 0.680 |
| **同人评估 / 跨人评估** | 用本人数据训练测试 / 用他人数据测试 | 主实验做同人；跨人明显更差 |
| **消融实验**（ablation） | 逐个去掉某个设计，看指标变化，证明它有用 | 见 5.3、8.4 |
| **基线**（baseline） | 用来对比的传统方法 | LDA + 时域特征 |

### A7 部署

| 术语 | 解释 | 本项目 |
| --- | --- | --- |
| **推理**（inference）/ **延迟**（latency） | 用训练好的模型算一次结果 / 花多少时间 | 每 50 ms 出一次结果 |
| **模型导出**（export） | 把训练框架的权重转成通用格式 | `.pt` → `.npz` |
| **纯 NumPy 前向** | 用普通数学库重写一遍推理，不依赖 PyTorch | `numpy_infer.py`，误差 <1e-6 |
| **滑动缓冲 / 预热**（warm-up） | 实时流式攒够一个窗口再推理 / 开头不足时的等待期 | 攒 100 ms；前 1.7 s 不输出 |
| **校准**（calibration）/ **仿射变换** | 用少量数据修掉系统性偏差；仿射 = 乘一个系数再加一个常数 | 验证集拟合 `y≈a·ŷ+b` |
| **量化 / 剪枝**（quantization / pruning） | 把参数从 32 位压到 8 位 / 删掉不重要的连接，便于上嵌入式 | 下一步计划 |
| **插件接口**（plugin API） | 上位机规定的算法接入约定：`NAME` / `TYPE` / `predict(ctx)` | 两个插件已按此实现 |

1. **电极位置/通道对应关系**：NinaPro 的 8 路是前臂一圈均匀分布，
   本项目手环贴在特定肌肉上（拇短展肌、指浅屈肌、指伸肌…），通道顺序并不等价。
   更稳妥的做法是用自己采的数据（上位机「交互训练」页导出的 CSV）做**迁移学习/微调**，
   公开数据集负责“预训练 + 方法验证”。
2. **个体差异**：跨受试者通用模型明显不如逐人模型（第 5 节有对比），
   实际使用建议开机做一次 30 s 校准或每人录 1–2 轮数据微调。
3. **休息类占比高**：测试集里休息样本接近一半，所以“整体准确率”会被休息类抬高，
   报告里同时给了「仅动作样本准确率」和宏平均 F1，这两个更能反映真实水平。
4. 后续可以把模型量化成 INT8、剪枝后搬到 ESP32-S3 上，或者用上位机录的数据做在线微调。
